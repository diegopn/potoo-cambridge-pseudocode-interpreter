# Cambridge pseudocode reference coverage

This crate targets the documented 9618 pseudocode in the 2026 and 2027–2029 teacher guides. Both editions currently use the same implemented grammar profile. The selected edition is retained in the parsed program and execution result.

| Reference area | Implemented behavior | Remaining boundary |
| --- | --- | --- |
| Scalar and array types (both guides, §§2–3) | `INTEGER`, `REAL`, `CHAR`, `STRING`, `BOOLEAN`, calendar-validated `DATE`, global and routine-local literal constants, fixed arrays with explicit lower and upper bounds, one-based or declared-bound indexing, and complete-array assignment when shapes and element types match | Array input is passed to `Host::input_value`; the guide does not define a text serialization format. |
| Enumerated types (both guides, §4.1–4.2) | `TYPE Name = (Member1, Member2, ...)`; members are immutable named values, variables default to the first member, comparisons use declaration order, and adding or subtracting an integer selects an in-range member, as shown by the pointer example | No general ordinal-conversion routine is defined in the selected guides. |
| Record types (both guides, §4.1–4.2) | `TYPE` / `ENDTYPE` declarations, declared scalar or array fields, arrays of records, field reads and writes using dot notation, assignment between values of the same record type, and typed `INPUT` through `Host::input_value` | Recursive by-value records are not accepted. The host chooses how to collect structured input because the guides give no field serialization format. |
| Set types (both guides, §4.1) | `TYPE Name = SET OF Type` declarations, `DEFINE Name (values) : SetType` immutable constants, duplicate collapse, and typed `INPUT` through `Host::input_value` | Set membership and mutation operators are not described in the selected guides. The host chooses how to collect a set because no text format is specified. |
| Pointer types (both guides, §4.1–4.2) | `TYPE Name = ^Type`, address-of `^Target`, and postfix dereference `Pointer^` for reading, writing, and integer-offset arithmetic on enumerated values; pointer assignments enforce target types, and typed `INPUT` can be supplied by a host | Dereferencing an uninitialized pointer reports a null-pointer error. Addresses to routine-local storage expire on return. The host must supply a pointer address meaningful to the current interpreter; the guides define no serialized address format. |
| Expressions and control (both guides, §§2 and 5) | Arithmetic, Boolean and comparison operators, string concatenation, conditionals, `CASE`, loops, input/output, and function calls | Syntax or behavior outside the selected guides is not inferred from a general-purpose programming language. |
| Procedures and functions (both guides, §6) | `BYVAL`/`BYREF` procedure parameters, inherited parameter mode across following parameters, `BYVAL` function parameters, local declarations, recursion, and function returns; `BYREF` aliases caller variables, record fields, and array elements during the call | Function `BYREF`, `RETURN` from a procedure, and a call in the wrong context are rejected. |
| Standard routines (both guides, §7) | `LENGTH`, `RIGHT`, `MID`, `LCASE`, `UCASE`, `INT`, and host-provided `RAND` | Any library facility not listed above is unavailable. |
| Text and random-access files (both guides, §9) | Text modes `READ`, `WRITE`, and `APPEND`; `READFILE`, `WRITEFILE`, `EOF(file)`, `CLOSEFILE`; random mode with `SEEK`, `GETRECORD`, and `PUTRECORD`; mode and value types are checked | The CLI implements text files. Random-record operations require a `Host` file service; the host owns paths, permissions, encoding, and record storage. |
| Object-oriented features (both guides, §10) | `CLASS` / `ENDCLASS`, typed fields, public-by-default and explicit `PUBLIC` / `PRIVATE` visibility, object properties, procedure/function methods, `NEW` construction, single inheritance, inherited method lookup, and `SUPER` calls. Private members are checked at runtime. | Complete-object `INPUT` has no property serialization format in the guides. Object assignment requires the declared class to match. |
